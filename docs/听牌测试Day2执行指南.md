## 📊 测试用例详解

### Test Case 2.1: 基础听牌 (听1种牌)

**目的**: 验证系统能正确识别只差1张牌胡牌的情况

**手牌组成**:
```
万1 万2 万3    (顺1)
万4 万4 万4    (刻1)
筒5 筒5 筒5    (刻2)
条6 条6 条6    (刻3)
字1            (缺1张眼) ← 还差字1就能胡牌

总计: 13张
```

**预期结果**: 
- ✅ 能识别为可听牌
- ✅ 听数应该是 1-2 种
- ✅ 可听牌应该包含 字1

---

### Test Case 2.2: 多种听牌

**目的**: 验证系统能识别多种听法

**手牌组成**:
```
万1 万2 万3    (顺1)
万4 万5 万6    (顺2)
筒7 筒8        (缺1张完成顺/刻)
条1 条2 条3    (顺3)
字1 字1        (眼)

总计: 13张
```

**预期结果**:
- ✅ 听数应该 > 1 种
- ✅ 可能能听 筒6、筒7 等多种牌

---

### Test Case 2.3: 无法听牌 (距离太远)

**目的**: 验证系统能正确拒绝距离太远的手牌

**手牌组成**:
```
万1 万2        (缺万3)
万4 万4 万4    (刻)
筒5 筒5 筒5    (刻)
条6 条6 条6    (刻)
字1 字1        (眼)

总计: 13张
```

**预期结果**:
- ✅ 听数应该是 0
- ✅ 无法听牌 (距离 > 1张)

---

### Test Case 2.4: 复杂听法

**目的**: 验证系统能识别复杂的多听法情况

**手牌组成**:
```
万1 万2 万3 万4 万5  (可听多个牌)
万6 万6              (可组成对或刻)
筒1 筒1 筒1          (刻)
条2 条2 条2          (刻)
字3                  (缺眼)

总计: 13张
```

**预期结果**:
- ✅ 听数应该 > 2 种
- ✅ 系统能正确计算多种听法

## 🐛 如果出现错误

### 错误1: "check_can_hear is not defined"
**原因**: WinChecker 没有 check_can_hear 方法  
**解决**: 检查 win_checker.gd 是否存在此方法

### 错误2: "Test case 2.X failed"
**原因**: 听牌逻辑可能有问题  
**解决**: 查看测试输出，核对手牌组成是否正确

### 错误3: 听数计算不对
**原因**: 手牌组成设计需要调整  
**解决**: 重新审视测试用例的手牌构成
