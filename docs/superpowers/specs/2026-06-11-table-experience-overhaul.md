# 牌桌体验重做(Table Experience Overhaul)— 差异分析 + PRD

> 2026-06-11。参考对象:https://www.hellolvs.cn/mahjong/(「雀王」,React + framer-motion
> 网页麻将,同为 Claude Code 产出)。本文档基于对其线上 bundle(106KB CSS / 474KB JS)
> 的逆向分析 + 我方 `godot/ui/four_player_table/` 全量盘点,逐项给出差距与目标规格。
> 实施计划见 `docs/superpowers/plans/2026-06-11-table-experience-overhaul.md`。

## 0. 北极星

把**对局桌面**(布局、摸/切/吃/碰/杠/立直/胡的全链路视听反馈)提升到参考作的
体验水准。肉鸽 meta 层(地图/商店/抽卡)不在本期范围。

一句话目标:**让牌成为画面的主角,让每个动作都有"被演出"的重量感。**

---

## 1. 深度差异分析

### 1.1 舞台与桌面(差距:大)

| 维度 | 雀王(参考) | 我们(现状) |
|------|------------|--------------|
| 设计画布 | 1600×900 固定 stage,`--stage-scale` 等比缩放居中,溢出裁切 | 1280×800 viewport,table 1080×720 + 右侧 200px AbilityPanel |
| 桌面质感 | 3D 透视(`perspective:1200px` + `rotateX(18deg)`);毛毡 `#1f5132` + SVG feTurbulence 程序化噪声纹理;左右**木质护栏**(渐变木纹 + 2px 暖白高光线 + 多层投影) | 平面俯视,纯色 BG_BASE + 一张整图背景,无桌沿结构 |
| 画面主角 | 牌(玩家手牌 lg 52×72+,贴底部 30px,带 3D 立牌边缘) | SeatPanel 信息框(240×100 色块)视觉权重高过牌(40×60) |
| 中心区 | 220×220 圆角深蓝面板:四方分数+风位、**立直棒指示灯**(亮起时金条+发光红点)、装饰对角线、金色描边 | 240×160 纯文本面板(局数/dora/墙余/棒数文字) |
| 座位信息 | 头像(44 张 webp 立绘+缩略图)+名字+段位+分数(`tabular-nums`)+当前回合金点(发光) | 64×80 立绘(3 张 AI)+文本名+分数,ActiveGlow 金边 |

**关键洞察**:对方把"信息框"打散成贴边的轻量元素(头像角标、中心盘四边分数),
桌面中央全部留给牌河与牌;我们的 4 块 SeatPanel 色块把桌面切碎了。

### 1.2 牌的渲染(差距:大)

参考作的牌是 DOM 元素 + 分层伪元素,有完整的**单牌状态机**:

| 状态 | 雀王做法 | 我们现状 |
|------|----------|----------|
| 基础 | 圆角 5/5/6/6(上小下大,实体牌形),双层 box-shadow(2px 锐影 + 4px 漫射) | 80×120 贴图 + 2px 黑描边,无投影 |
| 玩家立牌 | 牌顶两条伪元素:10px 绿背边 + 5px 灰白棱 → "从后上方看站立牌"的 3D 错觉 | 平贴 |
| 对手侧视 | 左右家牌背用**横向渐变模拟牌侧面**(白面薄边 8%→绿背 92%),上家用纵向渐变 | 平面 back.png + 座位色 tint |
| 宝牌 | `.tile--dora`:2.4s 循环斜向高光扫过(115° 渐变 translate -140%→140%) | 无 |
| 选中 | `.tile--lifted`:抬起 14px + 金圈描边 + 双层 drop-shadow | 抬起 16px(有),无金圈 |
| 同名联动 | `.tile--hover-match`:悬停时全桌同名牌蓝色蒙版 | 无 |
| 最新弃牌 | `discard-glow` 1s 衰减光晕 | 2px 骨白描边(有,静态) |
| 和牌张 | `.tile--win` 专属 shock 脉冲(荣/自摸两套) | 无 |
| 暗色 | `.tile--dim`(非候选牌压暗,配合吃碰选择) | 无 |

### 1.3 动作宣告演出(差距:最大,这是"质感"的核心来源)

参考作的吃/碰/杠/立直/自摸/荣和全部走 **call-announce / win-announce 三层合成**:

```
结构: 座位方向定位(top/left/right/bottom 四变体,从动作发起座位滑入)
  ├─ 200px 圆形头像  slide-in 0.5s cubic-bezier(.16,1,.3,1)
  └─ 书法大字 chip(90px/胡 108px,font-anime 书法字体)
       ├─ 本体: 白字 + 9px 彩色描边(paint-order: stroke fill)+ 按动作配色
       │        (吃=绿 #2eb872 / 自摸=红 #e63a28 / …)+ 多层 drop-shadow 辉光
       ├─ :before = 同字 blur(22px) 光晕,1.1s ease-out 绽放
       └─ :after  = 圆环冲击波,0.75s 从 60px 扩散淡出
```

我们现状:顶部金色 toast 文字 1.5s + 全屏白闪 + 屏震。**是"通知",不是"演出"**。

### 1.4 胡牌结算(差距:大)

| 阶段 | 雀王 | 我们 |
|------|------|------|
| 宣告 | win-announce(108px 书法大字+头像+光晕+冲击波,1.4s) | toast + 粒子 + 屏震 |
| 翻牌 | `hand-reveal-in` 对手手牌翻开动画 | 无(直接弹面板) |
| 结算面板 | 毛毡渐变底+金边 modal,backdrop blur(3px) | Panel popin(已有) |
| 役列表 | **逐条入场** `yakuRevealIn` 0.26s/条 错峰 | 一次性整段文本 |
| 分数 | **数字滚动** deltaRoll + is-up 金/is-down 红辉光,30px 加粗 | 静态文本列表 |
| 胡牌手 | 34×45 小牌行,和牌张横置 | 28×40 小牌行+金框(已有) |

### 1.5 发牌(差距:中)

参考作有完整 `deal-anim`:开局牌从中心飞向四家(per-seat 投影方向不同),
`is-dealing` 期间真手牌隐藏。我们只有 1.3s 文字 splash。

### 1.6 字体即美术方向(差距:中,性价比最高)

参考作用两款书法字体(Ma Shan Zheng 毛笔楷 + Liu Jian Mao Cao 草书)专门服务
宣告大字,且在 mount 前 `document.fonts.load` 预热防字形闪变。我们已有霞鹜文楷
(正文),缺**宣告专用书法 display 字体**。

### 1.7 架构约束(实施前必须正视)

我方 `bind_battle_state` 是**全量重建**(每个 BC 事件 queue_free 全部河/副露子节点
重建)。这意味着:
- 牌不是稳定节点 → **无法做"牌从 A 飞到 B"类动画**(弃牌飞入河、发牌飞向手牌、
  鸣牌飞向副露区)。
- 参考作是 React diff,牌节点稳定,配合 framer-motion 的 layout 动画天然支持飞行。

→ 凡是需要牌飞行的演出(发牌动画、弃牌入河),前置条件是**河/手牌增量更新改造**
(详见 plan T5)。其余演出(宣告大字、单牌状态、结算编排)不依赖此项,可先行。

## 2. PRD

### 2.1 目标(按优先级)

1. **G1 宣告演出系统**:吃/碰/杠/立直/自摸/荣和触发书法大字三层合成演出,
   从动作座位方向入场,按动作配色。替换 toast 通道(toast 保留给次要信息)。
2. **G2 单牌状态系统**:CardTileBack 支持 dora-shine / lifted金圈 / hover-match /
   win-pulse / dim 五个新状态,渲染层接入。
3. **G3 桌面舞台重做**:毛毡纹理 + 木护栏桌沿;中心盘重做(四方分数/风位/
   立直棒指示灯);SeatPanel 瘦身为贴边头像信息条,把桌面让给牌。
4. **G4 结算编排**:win-announce → 结算面板内役种逐条入场 → 分数滚动 → 总分条。
5. **G5 发牌动画 + 增量渲染**:河/手牌增量更新改造,开局发牌飞行演出。

### 2.2 非目标

- 3D 透视桌面(`rotateX` 等价物)。Godot 2D 下需 SubViewport+mesh 或全套美术重画,
  成本/风险不成比例。列为 future,本期用"侧视牌背渐变 + 立牌边缘"拿到 70% 纵深感。
- 联机、移动端适配、肉鸽 meta 层 UI、coach 教学系统。
- 换引擎/换栈。Godot 能逐项落地上述全部目标(宣告=Control+Anima,
  扫光=shader 或动画遮罩,纹理=程序化生成烘焙 PNG)。

### 2.3 体验需求(验收标准)

**AC-G1 宣告演出**
- a. 任一鸣牌/立直/胡触发时,屏幕出现 ≥72px 书法大字 + 该座位头像,从对应座位
  方向滑入(下家右侧入、对面顶部入、上家左侧入、自家底部入)。
- b. 大字三层:本体彩色描边字 + 模糊光晕绽放 + 圆环冲击波,总时长 0.9-1.4s,
  不阻塞对局(纯 overlay,pointer-events 穿透)。
- c. 配色:吃绿/碰蓝/杠橙/立直金/自摸红/荣和红金。
- d. GUT:演出节点生命周期测试(创建→自毁,无孤儿);手测场景 F6 可逐个预览。

**AC-G2 单牌状态**
- a. 宝牌(与指示牌对应的实牌)在手牌/河/副露中带循环扫光。
- b. 玩家点选手牌:抬起 + 金圈;悬停:全桌同名牌高亮蒙版。
- c. 和牌张在结算前有专属脉冲;吃牌选择模式中非候选牌压暗(dim)。
- d. 状态为 CardTileBack 标志位,bind 全量重建后状态仍正确(由 caller 重新标记)。

**AC-G3 桌面舞台**
- a. 桌面有毛毡纹理 + 左右木护栏,中央无大色块遮挡;截图对比旧版,牌的视觉
  占比明显提升。
- b. 中心盘:四方显示各家分数+自风,立直家对应边亮立直棒指示灯;局数/本场/
  墙余保留。
- c. SeatPanel 不再渲染 240×100 底板;座位信息以头像+名字+分数轻量条贴边呈现。
- d. capture_screens 全场景通过,无布局回归(现有 GUT UI 测试全绿)。

**AC-G4 结算编排**
- a. 役种列表逐条入场(~0.26s/条错峰),每条带名称+飜数。
- b. 分数变化数字滚动(0→目标值,带 is-up 金/is-down 红辉光)。
- c. 总时长 ≤3s 可点击跳过(点击立即到终态)。

**AC-G5 发牌动画**
- a. 开局 13×4 张牌从中心按发牌顺序飞向四家(总时长 ≤2.5s,可设置关闭)。
- b. 河增量更新:新弃牌单独入场动画(落下+glow),旧牌节点不重建。
- c. 全套 GUT 0 fail;对局功能无回归。

### 2.4 视觉规格(从参考作换算到 1280×800)

- 玩家手牌:48×68(现 40×60),贴桌底,牌间 2px,摸牌位 +14px 间隙。
- 对手手牌:28×40 侧视渐变背(左右家竖排)。
- 河:38×50/张,6 列 3 行,贴中心盘四边。
- 中心盘:200×200(现 240×160)。
- 宣告大字:常规 80px / 胡牌 104px,书法字体,描边 8px。
- 头像:座位条 56px 圆;宣告演出 160px 圆。
- 配色 token(新增 DT):`GOLD #d9b65b`、`FELT_1 #1f5132`、`FELT_2 #173f27`、
  `ANNOUNCE_CHI #2eb872`、`ANNOUNCE_PON #3c8cbe`、`ANNOUNCE_KAN #e0862e`、
  `ANNOUNCE_RIICHI #d9b65b`、`ANNOUNCE_WIN #e63a28`。

### 2.5 风险

| 风险 | 缓解 |
|------|------|
| 全量 rebind 与动画冲突(新弃牌 glow 被下一事件重建打断) | G1-G4 演出全部挂 overlay 层(不在 rebind 子树);G5 才动 rebind 架构 |
| 书法字体含生僻字缺字 | 宣告字集固定(吃碰杠立直自摸荣和役満流局十余字),子集化时显式校验 |
| SeatPanel 瘦身牵连 emote/speech/badge 逻辑 | 保留 SeatPanel 节点接口不变,只改其内部绘制 |
| 性能(扫光 shader × 14 手牌) | 扫光只在宝牌上启用(通常 ≤4 张);用 AnimationPlayer 驱动 UV offset,无逐帧 GDScript |
