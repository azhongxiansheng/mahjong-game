# 欢乐场道具能力玩法设计（v1 草案）

> 日期：2026-07-28
> 状态：玩法设计稿，尚未授权修改生产效果
> 适用模式：嘴强欢乐场；标准场继续在构造期禁用全部道具
> 事实基线：`ItemCatalog` 当前登记 10 个战斗消耗品、12 个遗物；代码当前允许发放 19 个，本稿为全部 22 个定义正式能力

## 1. 设计目标

道具应放大欢乐场的判断、逆转和嘴仗反馈，但不能取代日麻的基本决策：

1. **先有合法和牌，再结算道具加成。** 道具提供的番、Dora 不得凭空创造役。
2. **效果可预测。** 玩家在使用前能从一句规则文本判断触发时机、对象、持续时间与消耗条件。
3. **信息只影响决策，不篡改客户端权威。** 窥牌结果仅向受益席投影，牌墙与结算仍由 Worker 决定。
4. **多实例可解释。** 同 ID 实例仍保持独立身份；消耗品逐件使用，遗物按本文规则线性或分层叠加。
5. **避免同质化。** 防御、信息、节奏、Dora、条件增番和逆转各有不同决策窗口。
6. **高风险能力先冻结规则，再分批实现。** 换座、手牌交换和跨局保底必须经过专用权威流程，不能用空 Hook 或数组交换冒充完成。

## 2. 全局规则

### 2.1 道具类型

| 类型 | 获取后状态 | 使用方式 | 跨局 | 多实例 |
|---|---|---|---|---|
| 即时消耗品 | `held` | 在自己的合法决策窗口主动使用，成功后立即生效并消耗 | 未使用实例保留到整场结束 | 每次命令只指定并消耗 1 个实例 |
| 武装消耗品 | `held` | 主动使用后变为 `armed`，命中条件时生效并消耗 | 未触发时跨手牌保留武装 | 同 ID 同席同时最多武装 1 个，其余保持 `held` |
| 遗物 | 获得后立即生效 | 无主动按钮 | 保留到整场结束 | 每个实例独立注册；叠加方式由单件规则明确 |

主动使用只允许发生在使用者拥有行动权、牌局未进入 CLAIM/结算/奖励屏障时。失败的使用不消耗实例。

### 2.2 结算顺序

同一事件按以下玩法顺序处理：

1. 校验日麻原始行动与原始役；
2. 处理“取消荣和”类效果；
3. 处理条件增番、额外 Dora；
4. 处理番数倍率与上限；
5. 计算本次和牌点数；
6. 处理基于“本次实际得点”的返还或转移；
7. 发布 `ITEM_APPLIED` / `ITEM_CONSUMED`，客户端只投影权威结果。

同一弃牌出现多家荣和时，取消类道具以完整 CLAIM 结果为边界，不依赖客户端动画先后。本文若写“本次弃牌产生的荣和”，指该弃牌的整个多家荣和集合。

### 2.3 数值与取整

- 点数返还/转移统一向下取整到 100 点。
- 额外 Dora、额外赤 Dora 只增加计分番，不视为独立役。
- 负番防御只减少计分番，不移除原始役；最终计分番最低为 1。
- 不同名称的效果可以叠加；同 ID 武装消耗品不能同时武装多件。
- 遗物无通用叠加上限；需要非线性叠加的道具在自身规则内明确。

## 3. 消耗品正式玩法

### 3.1 正式设计 10 件

| ID / 名称 | 稀有度 | 类型 | 正式规则文本 | 叠加与边界 | 落地级别 |
|---|---|---|---|---|---|
| `iron_shield_v1` 铁盾 | 稀有 | 武装 | 武装后，你下一次打出的牌若产生荣和，取消该弃牌产生的全部荣和，然后消耗。 | 对自摸无效；一次保护整个多家荣和集合。 | L2 |
| `wall_peek_v1` 千里眼 | 普通 | 即时 | 查看当前牌墙接下来 3 张牌的顺序。信息仅你可见，直到这些牌离开牌墙或本局结束。 | 多次使用会刷新并扩大当前可见集合，不改变牌序。 | L1 |
| `double_payout_v1` 倍率券 | 史诗 | 武装 | 你下一次合法胡牌时，结算前将总番数翻倍；由此额外获得的番数最多为 3，然后消耗。 | 在额外番、Dora 加入后计算；役满不再放大。 | L2 |
| `dora_charm_v1` 宝牌护符 | 史诗 | 武装 | 你下一次合法胡牌时额外获得 2 Dora，然后消耗。 | 不创造役；荣和、自摸均可触发。 | L1 |

| `furiten_bomb_v1` 振听炸弹 | 史诗 | 武装 | 武装后，下一名对手声明的荣和被取消，然后消耗。 | 不要求该荣和来自你的舍牌；对自摸无效。这是欢乐场的全桌干扰牌。 | L0 |
| `point_shield_v1` 点棒护盾 | 史诗 | 武装 | 你下一次放铳正常结算后，从和牌者本次因荣和获得的点数中返还 30% 给你，然后消耗。 | 只按本次荣和净得点计算，不按和牌者总分；不返还立直棒，不影响其他付款席。 | L2 |
| `tsubame_v1` 燕返（暂名） | 稀有 | 配牌后即时 | 下一局配牌后、第一次行动前，选择 1–3 张手牌置于活牌墙底，再从活牌墙顶补回相同数量。 | 每名玩家每局最多成功使用 1 次；补牌不触发摸牌类能力；生产名称仍需 IP 审查。 | L3 |

`落地级别` 含义：L0 为现有机制基本吻合；L1 为参数、条件或文案级调整；L2 需要扩充事件上下文或权威结算路径；L3 需要新增专用交互窗口与公共协议。它不是优先级。

### 3.2 消耗品的决策定位

- **铁盾**是可预期的个人防守牌，保护一次自己的危险弃牌。
- **振听炸弹**是全桌干扰牌，能救别人、破坏领先者，也可能改变同盟关系；其史诗稀有度用于控制出现频率。
- **点棒护盾**不否定和牌，只降低一次放铳代价，与铁盾形成“取消结果 / 缓和结果”的区别。
- **千里眼**提供计划能力；**牌墙崩塌**改变剩余时间；两者共同形成信息与节奏组合，但不直接给分。
- **翻宝牌**是公开风险投资；使用者可基于自己手牌判断收益，但其他三家同样可能受益。
- **宝牌护符**提供稳定爆发；**倍率券**奖励原本已经较高的牌型，但额外番上限避免普通和牌直接跃迁役满。
- **燕返**允许修正烂配牌，但选择数量有限且会把被换出的牌放到墙底，不保证直接改善向听数。
- **换座**允许抢庄、改变自风和行动次序，是整场级战略牌，因此稀有度和实现门槛都高于普通战斗 Hook。

| 构筑方向 | 代表组合 | 玩法收益 | 主要制衡 |

## 5. 三件新增能力的专用边界

### 5.1 换座

- 只能在一局结算完成、下一局配牌尚未开始的公开准备窗口使用；不能在牌局中交换。
- 使用命令必须指定另一名玩家，不能选择自己；交换成功后才消耗实例。
- 玩家身份拥有分数、角色、库存、连接与统计；座位拥有庄家、自风、摸打顺序和桌面方位。交换只改变身份到座位的映射。
- 已完成的局、场风、本场棒、立直棒和奖励结果不回滚；若下一局预定庄家座被交换，新占据该座的玩家成为庄家。
- 交换永久持续到本场结束，且整场最多执行一次，避免多次交换造成位置追踪负担。

### 5.2 燕返

- 只能在初始手牌已权威配发、首个 `TURN_PROMPT` 尚未发出时使用。
- 使用者选择 1–3 个真实手牌实例；服务器按命令中的稳定顺序将它们置于活牌墙底，再从顶部补相同数量。
- 交换不会触发 `TILE_DRAWN`、岭上、海底或其他摸牌型技能，也不会改变王牌与宝牌指示牌区域。
- 交换前后手牌数量必须一致；任何实例不属于使用者、重复选择或窗口过期都整体拒绝且不消耗。
- 同一玩家同一局最多成功使用一次；额外实例留到后续牌局。

### 5.3 天命打破

- 每个实例记录同一玩家连续“本局未胡”的已完成牌局数；他家荣和、自摸、荒牌流局和途中流局均计 1。
- 玩家在任意牌局荣和或自摸后，所有天命实例的累计与充能状态重置。
- 连续两局未胡后实例充能；下次合法胡牌先应用满贯保底。若有 N 个已充能实例，再追加 N-1 番，避免多个满贯保底完全没有边际价值。
- 天命加成不能创造役，也不把原本役满继续放大；触发结算后所有已充能实例一并重置。
- 这是战斗内败者补偿，不再读取或修改任何 Run、抽卡或奖励池概率。

## 6. Affinity 建议

继续使用现有五类 affinity 作为垃圾话匹配标签，不让 affinity 放大道具效果。`换座` 保持 `CUNNING`，`燕返` 保持 `PASSION`；新版 `天命打破` 设为 `MYSTIC`。

22 件全部启用后的主 affinity 数量为：`CALM 4 / CUNNING 4 / DOMINATION 5 / PASSION 5 / MYSTIC 4`。差值不超过 1，无需为了凑数扭曲单件主题。

## 7. 首轮平衡观测

实现后不先凭感觉连续改数值，而以固定 seed 的欢乐场回归记录以下指标：

| 指标 | 首轮观察目标 |
|---|---|
| 道具实际触发率 | 消耗品 35%–70%；低于 20% 说明触发条件或 UI 时机不清楚 |
| 单件平均点数影响 | 普通 < 稀有 < 史诗；信息类单独看胜率变化，不硬折算点数 |
| 取消荣和占比 | 不超过全部合法荣和的 15% |
| 平均每场未使用消耗品 | 不超过获得消耗品的 40% |
| 遗物重复实例占比 | 记录 1/2/3+ 件时的边际收益，重点观察墙眼、铁壁意志、魂镜 |
| 逆转效果 | 末位席获得逆转王冠后的最终名次改善，但不能让单件稳定抹平 12000 点以上差距 |
| 信息泄漏 | 非受益席 projection 中不得出现窥见牌的实体或顺序 |

## 8. 实现拆分建议

本稿确认后，按风险拆成四批，而不是一次改完 22 个能力：

1. **规则对齐批（L0/L1）**：修正文案与参数，完成宝牌护符、千里眼、铁壁意志、红线、逆转王冠等条件测试。
2. **计分上下文批（L2-score）**：为倍率上限、役种条件、个人舍牌数、本次实际得点建立只读上下文与统一结算 API，再迁移倍率券、点棒护盾、魂镜、龙印、风铃、速攻鬼、忍石。
3. **权威流程批（L2-flow）**：以完整 CLAIM 聚合铁盾的多家荣和语义，实现公开翻宝牌、墙眼多层预知和天命打破的跨局计数。
4. **准备窗口批（L3）**：先实现燕返的配牌后选择窗口并完成实体牌/牌墙回放验证；最后单独实现换座的身份—座位映射和公共协议。

每批都应先写真实 GUT 失败用例，再做最小实现；协议 DTO、`ItemInstance` 生命周期和 `ITEM_*` 事件包络默认不变。若某项必须改变公共事件 schema，应独立立项并升级全量验证。

## 9. 本稿默认决策

若无进一步产品修改，后续实现以以下结论为准：

- 全部 22 件均有正式能力；生产启用仍按 L0/L1 → L2 → L3 分批完成，不能只改 `reward_eligible` 提前发放空效果。
- 道具不创造役，隐藏信息按席投影，点数转移以本次结算为基数。
- 同 ID 武装消耗品同时最多 1 件；遗物实例继续独立叠加。
- “翻宝牌”改成真正公开翻指示牌，不再保留“下一次摸牌凭空 +1 Dora”的占位语义。
- 铁盾保护自己一次完整放铳事件；振听炸弹保留为可干扰全桌的史诗效果。
- 燕返优先于换座实现；天命打破采用“连续两局未胡，下一次胡牌满贯保底”的战斗语义。
- 先保守设定数值，再通过固定 seed 的整场数据调整，不在首轮加入套装、商店或 Run 系统。
