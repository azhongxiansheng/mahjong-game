## 🔍 问题原因 - 深层分析

### 🎯 **根本原因：初始化顺序竞争条件**

三个错误都源自同一个根本问题，但表现方式不同：

```
问题链:
1. main.gd 调用 initialize_game_ui()
   ↓
2. GameUI 节点被获取 (通过 get_node_or_null)
   ↓
3. 立即调用 game_ui.test_display_hand()  ❌ 太早！
   ↓
4. 此时 GameUI._ready() 可能还没执行
   ↓
5. @onready 变量仍未初始化 (== nil)
   ↓
6. test_display_hand() 调用其他方法
   ↓
7. 这些方法尝试访问 nil 对象的属性 → 运行时错误
```

### 📊 问题细节

| 阶段 | 状态 | 结果 |
|------|------|------|
| GameUI 节点获取 | ✅ 完成 | 节点存在 |
| GameUI._ready() | ⏳ 可能未完成 | @onready 为 nil |
| test_display_hand() 调用 | ❌ 太早 | 使用 nil 变量 |

---

## ✅ 完整解决方案

### 解决方案1：使用 call_deferred 延迟调用 ⭐ **关键修复**

**文件**: `godot/scripts/main.gd`

**错误代码:**
```gdscript
func initialize_game_ui() -> void:
    game_ui = get_node_or_null("UILayer/GameUI")
    if game_ui:
        print("✓ GameUI已初始化")
        game_ui.test_display_hand()  # ❌ 立即调用 - 太早！
    else:
        print("⚠ 无法初始化GameUI")
```

**修复代码:**
```gdscript
func initialize_game_ui() -> void:
    game_ui = get_node_or_null("UILayer/GameUI")
    if game_ui:
        print("✓ GameUI已初始化")
        # ✅ 延迟到下一帧，确保 GameUI._ready() 已执行
        game_ui.call_deferred("test_display_hand")
    else:
        print("⚠ 无法初始化GameUI")
```

**为什么有效:**
- `call_deferred()` 将方法调用推迟到当前帧完成后
- 这给了 GameUI._ready() 时间来初始化所有 @onready 变量
- 当 test_display_hand() 执行时，所有变量都已就绪

### 解决方案2：GameUI 中的 @onready 回收机制（防护层）

**文件**: `godot/scripts/game_ui.gd`

```gdscript
func _ready() -> void:
    print("========== GameUI 初始化 ==========")
    super()
    
    # 防护性初始化：手动初始化任何失败的 @onready 变量
    _initialize_missing_nodes()
    
    setup_ui()
    connect_signals()
    apply_theme()
    print("========== GameUI 初始化完成 ==========")

func _initialize_missing_nodes() -> void:
    """初始化任何失败的 @onready 节点 - 防护性编程"""
    if not player_hand_display:
        player_hand_display = get_node_or_null("GameLayer/TableArea/PlayerHand")
        print("⚠ player_hand_display 从 @onready 重新获取: %s" % 
              ("成功" if player_hand_display else "失败"))
    
    # ... 其他节点 ...
```

### 解决方案3：全局 Nil 安全检查（防御层）

**文件**: `godot/scripts/game_ui.gd`

```gdscript
func add_log_message(message: String) -> void:
    """添加日志消息 - 安全版本"""
    if not game_log:
        print("[WARN] game_log 为 nil，日志消息: %s" % message)
        return
    
    # 添加文本前验证属性存在
    if not game_log.has_property("text"):
        print("[ERROR] game_log 没有 text 属性")
        return
    
    # 安全访问
    game_log.text += "[%.1f] %s\n" % [Time.get_ticks_msec() / 1000, message]
```

## 📚 深层理解

### 为什么 Godot 的初始化是异步的？

Godot 使用树形场景系统，当一个节点被添加到树中时：

```
时间线:
0ms: 节点加入场景树
1ms: _enter_tree() 被调用
2ms: @onready 变量被初始化
3ms: _ready() 被调用
4ms: 节点完全初始化，可以使用
```

如果在第3ms 时调用需要 @onready 变量的方法，就会失败！

### call_deferred 的作用

```
时间线:
0ms: 节点加入场景树
1ms: initialize_game_ui() 执行
2ms: call_deferred("test_display_hand") 注册
3ms: 当前帧执行完毕
     ↓
4ms: 下一帧开始
5ms: test_display_hand() 执行 ← 此时 @onready 已完全初始化
```
